# 国奖评委读者模型

## 这个模型解决什么

它帮助 Agent 判断“论文是否把已完成的建模工作写成评委能迅速理解、核验和比较的竞赛答案”。它不是评分表，也不是版式模板。

官方依据与推导边界见：

- `references/distill/source-notes/2025-reviewing-commentary.md`
- `references/distill/source-notes/2025-c-commentary.md`

## 评委先寻找的四件事

1. **你如何理解题目。** 任务对象、目标、约束和题间依赖是否准确。
2. **你的主答案是什么。** 每问是否有明确关系、参数、边界、方案、时点、规则或名单。
3. **答案凭什么成立。** 方法与数据结构是否匹配，结果是否有表图、对照或诊断支持。
4. **答案在什么条件下有效。** 假设、误差和适用边界是否改变结论或行动。

如果其中任一项需要评委在多页文字中自行拼接，论文就没有形成强作答闭环。

## 首页阅读模型

首页不是论文目录的缩写，而是整份答案的“可索引界面”。读者应能获得：

- 总体问题被怎样拆解；
- 各问采用什么思路，而非只看到模型名；
- 最关键的定量结果或决策；
- 一个值得继续阅读的本题特色；
- 关键词能否对应真正的建模骨架。

### 30—90 秒压力测试

这是内部设计测试，不是官方规则。隐藏正文后，只读标题、摘要、关键词和首个总览图，回答：

- 能否复述每问的主答案？
- 能否区分主模型与辅助模型？
- 能否指出至少一项结果证据？
- 能否知道论文的本题贡献是什么？

若只能复述模型清单，首页失败；若只有结论但没有证据口径，首页也失败。

## 每问的阅读顺序

评委通常不需要按作者的推导顺序理解答案。更有效的组织是：

读者最终需要理解该问真正要求的决策或判断、主答案与评价口径、模型为何适配、最有判别力的证据，以及行动含义与边界。

这些是阅读中应获得的信息，不是五步章节模板。关系解释、分组、时点、优化和判定可以采用不同顺序；不要求所有章节都“结论先行”，但要求读者始终知道当前推导服务于什么答案。

## 主答案与情景答案

题目允许多情景时，情景用于说明结论如何变化，不用于逃避选择。

- 先给基准情景下的主方案。
- 再指出哪些条件变化会触发另一方案。
- 如果无法唯一选择，明确缺少的判别信息，并给当前证据下的推荐。
- 不把“方案 A、B、C 各有优点”作为最终结论。

## 限制应放在哪里

- **改变模型解释的限制**：紧跟模型假设或参数解释。
- **改变结果置信度的限制**：紧跟结果和验证。
- **改变行动方案的限制**：紧跟建议、边界或触发条件。
- **仅属扩展方向的内容**：放在模型评价或展望。

全文末尾可以归纳，但不能让正文里的强结论直到最后才被修正。

## 方法自包含

评委无需根据引用反向猜测方法。正文至少应说明：

- 输入对象与观测单位；
- 核心变量或状态；
- 目标、关系或判定准则；
- 关键假设如何对应数据结构；
- 输出如何成为该问答案；
- 用什么证据验证。

引用用于说明来源，不能代替本题中的建模定义。

## 信息密度与图表节奏

高信息密度不是把内容塞满页面，而是减少无结论信息。

- 一张图服务一个主要判断；需要同时表达多个判断时，使用有共同叙事的多面板。
- 答案、证据和解释尽量相邻。
- 机制图解释对象或流程，结果图证明关系或差异，表格承载精确答案。
- 删除重复题意、重复公式、重复趋势图和只为“显得高级”存在的方法介绍。

## 最终语义检查

不要给分，直接回答：

- 评委第一页会如何复述这篇论文？
- 评委能否用自己的话简洁复述每问的主答案？这不要求作者在正文中预先写一条固定句式。
- 最容易被质疑的证据断点在哪里？
- 哪个方法看似复杂却没有改变答案？
- 哪个局限会真正改变建议，是否已放在对应位置？
