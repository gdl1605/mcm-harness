# C 题数据工程模块设计

> 本文定义数据工程模块的职责、Agent Team、波次、开放交接、数据分层和回滚原则。具体调度入口仍是根目录 `AGENTS.md`；语义内容使用 Markdown，不使用固定 JSON schema。

## 1. 模块目标与边界

数据工程把原始附件转化为各问可消费、可复现、可追溯的数据基础。它要回答的不是“怎样让某个模型效果更好”，而是：

- 题目中的对象在数据里怎样表示；
- 主键、粒度、时间和单位是否一致；
- 哪些量是观测、派生、潜在、proxy、标签或决策量；
- 哪些清洗和转换有题面或数据依据；
- 每问可以使用哪些数据，不能使用哪些信息；
- 处理后数据怎样从原始附件重复生成；
- 数据处理怎样影响题间接口和最终交付。

模块入口：

- `inputs/source-manifest.json`；
- 原始题面、附件、说明和答卷模板；
- `synthesis/problem-baseline.md`；
- `routes/route-handoff.md`；
- 前半程与数据有关的原始 memo、复核和未决争议。

模块终点：`data/data-handoff.md`。完成后进入建模模块，但不在本模块内训练模型、优化求解、按模型成绩筛选处理方案、制作最终论文图或写正式论文。

已实现文件索引：

- Leader 规则与阶段文件路由：`AGENTS.md` 第 3.2 节；详细逐波调度：`Workflow/README.md` 第 4 节；
- 团队配置：`Workflow/data-team.json`；
- Leader 与角色 prompt：`prompts/data-engineering/`；
- 开放交接模板：`templates/data-engineering/`；
- 初始化、prompt 拼装和机械检查：`scripts/`。

## 2. 为什么要拆 Agent，又不能拆得太碎

一个 Agent 同时解释字段、决定清洗、实现代码并验证自己，容易把路线需要偷偷写进数据。反过来，按表、字段或每个清洗步骤分给不同 Agent，又会产生冲突的主键、单位和缺失值口径。

因此按相互制衡的责任拆分：

1. 数据契约：从题目和路线定义需要什么；
2. 数据剖析：从附件事实确认实际有什么；
3. 数据风险：攻击自然解释和清洗路径；
4. 管道实现：由一个明确所有者统一实现共享数据；
5. 独立复核：重新运行并检查质量与题间接口；
6. Leader：综合、版本管理、分支和回滚。

角色可以按题目复杂度缩减，但数据实现者不能成为自己的唯一 reviewer。

## 3. Agent Team

### 3.1 Leader

Leader 负责：

- 从前半程提取每问数据需求、题间接口和禁止默认事项；
- 创建开放 task brief，隔离 D1 三个视角；
- 保存原始报告和 subagent 句柄；
- 综合数据方案，不以角色数量投票；
- 指定唯一数据管道实现者，避免共享数据被并行改写；
- 调度独立复现和接口复核；
- 决定局部修正、保留分支、重开题意或升级用户；
- 最后写数据交接。

Leader 不直接替代独立数据角色，也不把“不报错”或检查项数量当成数据可信证明。

### 3.2 数据契约架构师

从题意基线和路线交接出发，定义数据应当满足的语义和接口，但不直接清洗。

最低责任：

- 每问的对象、总体、分析单位、时间单位和输出对象；
- 观测量、派生量、潜在量、proxy、标签和决策量；
- 题间需要交换的数据对象、粒度、单位和可用时点；
- 共享规范数据与问题专属分析视图的边界；
- 数据模块必须生产和禁止生产的内容；
- 会改变题意或路线的关键数据假设。

### 3.3 数据剖析员

独立面对实际附件，确认数据真实结构，不按预想模型美化数据。

最低责任：

- 文件、sheet、表、字段、类型和编码；
- 主键候选、唯一性、重复模式和表间连接；
- 对象粒度、时间范围、频率、单位和覆盖范围；
- 缺失、零值、异常、结构性空白和不一致编码；
- 数据说明与实际附件的冲突；
- 未被路线使用但可能改变理解的表或字段。

允许进行结构和质量 EDA，不允许开始训练、求解或按模型效果修改数据。

### 3.4 数据风险审查员

独立搜索会使“管道运行正常但分析对象已经错了”的失败机制。

最低责任：

- 时间泄漏、目标泄漏、未来信息和事后变量；
- proxy、标签和题面概念之间的偷换；
- 聚合、筛选、连接、填补和异常处理造成的偏差；
- 重复测量被当作独立样本；
- 零值、缺失、未发生、不可观测和不适用被混淆；
- 多问对同一字段采用冲突口径；
- 答卷要求对象在处理中被删除或改变粒度；
- 清单之外的新数据风险。

### 3.5 数据管道实现者

根据 Leader 综合的数据方案统一实现共享数据管道。共享规范层只设一个实现所有者；若附件完全独立，可以并行开发读取模块，但最终合并仍由该所有者负责。

最低责任：

- 原始文件读取、编码和类型处理；
- 单位、对象、主键和时间标准化；
- 缺失、零值、重复、异常、筛选和连接处理；
- 规范数据层和每问分析视图；
- 可重复执行的代码、运行说明和必要测试；
- 每步处理前后的行数、对象数、时间范围及影响；
- 处理决策、未决语义和数据方法工程文稿。

实现者不得修改原始材料，不得用模型表现反向决定共享数据处理，也不得制造题面没有支持的标签。

### 3.6 复现与质量验证者

使用新的 subagent，从原始附件重新运行数据管道。

最低责任：

- 能否按说明从零生成全部处理后数据；
- 输出是否与处理日志和数据字典一致；
- 声明的主键、类型、单位和时间范围是否成立；
- 手工抽样能否映射回原始记录；
- 相同输入能否得到相同输出；
- 是否存在未记录的手工操作、外部依赖或隐式状态；
- 检查之外出现的新异常。

### 3.7 题间接口审查者

检查数据产物能否被各问和下游模块真正消费。

最低责任：

- 每问所需量是否真实可构造；
- 上下游对象、主键、粒度、单位和时间是否兼容；
- 数据口径是否被某个模型路线悄悄改变；
- 预测或决策时点是否只使用当时可得信息；
- 输出对象是否覆盖答卷要求的总体；
- 共享字段是否在不同问题保持同一含义；
- 哪些问题应回到数据方案、路线或题意基线。

简单单表题可以把它与复现验证者合并；多表、多时间尺度或题间强耦合时应独立。

## 4. 完整调度

### D0：Leader 接收与派工

Leader 读取前半程交接，建立本轮数据来源范围、不可修改文件、每问数据需求和三个隔离 task brief。此时不先决定清洗方法。

### D1：三路隔离调查

并行创建三个新 subagent：

1. 数据契约架构师；
2. 数据剖析员；
3. 数据风险审查员。

三者只看原始材料、前半程冻结交接和自己的 brief，不看彼此报告或 Leader 偏好，分别输出：

- `data/contracts/data-contract.md`；
- `data/profiling/data-profile.md`；
- `data/reviews/data-risk-review.md`。

### D2：Leader 数据方案综合

Leader 阅读三份原始报告，写 `data/decisions/preprocessing-plan.md`，至少说明：

- 当前数据分层和每问接口；
- 拟采用的处理及理由；
- 竞争处理方案与影响；
- 明确不处理或留到建模模块的内容；
- 需要回到前半程的问题；
- 版本、复现和审查安排；
- 三份报告中无法归类的新发现。

综合报告不能替代 D1 原始 memo。

### D3：统一管道实现

创建新的数据管道实现者。它可以读取 D1 报告和 Leader 数据方案，只能修改分配的数据工程代码、处理后数据、日志与工程文稿，不能修改原始材料和前半程产物。

主要输出：

- `data/pipeline/` 下的代码、运行说明和测试；
- `data/processed/canonical/`；
- `data/processed/analytical/`；
- `data/decisions/preprocessing-log.md`；
- `data/pipeline/implementation-memo.md`；
- `data/paper-notes/data-method-note.md`。

### D4：独立复核

实现完成后，按题目风险创建一到两个新的 subagent：

- 复现与质量验证者；
- 题间接口审查者。

它们可以读取原始材料、前半程交接、数据方案、代码、处理后数据和日志，但不能修改实现，分别写入 `data/reviews/reproducibility-quality-review.md` 与 `data/reviews/interquestion-interface-review.md`。

### D4R：原实现者修订

将复核报告连同 `data-builder-response.md` prompt 发回原数据管道实现者。它只能进行一次集中回应和修订：接受并修复、说明误解、保留竞争版本、请求数据语义复核或触发前半程重开，并写 `data/reviews/data-builder-response.md`。

首版代码、数据和 memo 不删除；新版本必须说明受影响的文件、问题和下游接口。

### D5：Leader 数据交接

Leader 写 `data/data-handoff.md`，至少交接：

- 当前可使用的数据版本与生成入口；
- 字段字典、主键、粒度、时间和单位；
- 共享规范层与每问分析视图；
- 处理决策、影响规模和数据质量事实；
- 允许使用、禁止使用和仍有争议的信息；
- 复现与接口审查结论；
- 建模模块必须遵守的边界；
- 需要局部回滚或重开前半程的触发器；
- 任务框架之外的新发现。

这是一份当前工作交接，不是“数据绝对正确”的证明。

## 5. 数据分层

### Raw 原始层

- 原始题面、附件、说明和模板只读；
- 保留原始路径、大小、时间和哈希；
- 不在原文件中改名、填值或调整格式。

### Staging 读取层

- 保存解析、编码、类型恢复和 sheet 展开后的中间结果；
- 尽量保持原始对象、行号和字段对应；
- 方便把处理记录映射回原附件。

### Canonical 规范层

- 统一对象标识、主键、时间、类型和单位；
- 只放跨问题共享、与具体模型无关的处理；
- 不包含根据目标表现选择的特征或人为标签。

### Analytical 问题分析层

- 按 Q1、Q2、Q3 等建立可消费视图；
- 记录聚合、筛选、时间窗和派生量；
- 不反向修改 Canonical 层；
- 题间共享对象必须保持一致接口。

### Model-specific 模型特征层

属于后续建模模块。数据工程可以定义输入边界，但不按某个算法、损失或成绩提前制作最终特征矩阵。

## 6. 必须遵守的原则

1. 原始材料只读，任何修复都另存并保留映射。
2. 先确认对象、主键、粒度、时间和单位，再讨论缺失与异常。
3. 每项处理记录“为什么、影响多少、可能改变什么”。
4. 缺失、零值、未发生、不可观测和不适用不得自动合并。
5. observed、derived、latent、proxy、label 和 decision quantity 必须区分。
6. 时间变量按真实可用时点审查，不以字段存在代替可用性。
7. 共享规范层保持模型无关；模型特定处理留到建模实验。
8. 不用模型性能反向决定共享数据清洗。
9. 处理后数据必须能由代码从原始材料重新生成。
10. 每个版本能追溯到来源、代码、处理决策和影响范围。
11. 模型 Agent 不直接修改共享数据；变更回到数据模块并产生新版本。
12. 语义交接使用开放 Markdown；JSON 只记录哈希、路径、版本、状态和运行参数。
13. 不把脚本无报错、检查项全绿或 reviewer 数量当成数据语义正确证明。
14. 任何框架外但会改变结论的发现都必须保留。

## 7. 机械检查与语义审查

可以机械检查：

- 文件、代码入口和依赖是否存在；
- 数据能否从原始材料重新生成；
- 输出哈希、表数、行列数和数据类型；
- 声明为唯一的键是否唯一；
- 连接覆盖、时间范围和单位转换是否符合记录；
- 日志中的处理数量是否与实际输出一致。

不能由脚本宣称：

- 某字段语义一定正确；
- 某种缺失处理一定合理；
- proxy 足以代表题面目标；
- 数据已经满足所有未知模型需求；
- 没有发现泄漏就证明不存在泄漏。

后者保留竞争解释、独立审查、反例和回滚条件。

## 8. 为建模和论文留档

数据模块向建模交接可执行数据，同时维护 `data/paper-notes/data-method-note.md`。工程文稿至少保留：

- 数据来源、对象、时间范围、单位和原始规模；
- 删除、保留、填补、聚合和派生处理；
- 每步处理影响的行数、对象数和时间点；
- 单位换算、标准化或其他转换公式与参数；
- 异常值和样本筛选依据；
- 最终分析粒度、样本规模和不可回答边界；
- 可作为论文数据描述表的统计结果；
- 不能被论文过度表述的限制。

它不是正式论文正文。后续论文模块从工程文稿、处理日志和结果索引扩写，不能重新猜测代码意图。

## 9. 完整模式与精简模式

出现以下任一情况时使用完整模式：

- 多表连接或多个附件；
- 多种对象或时间粒度；
- 重复测量或面板数据；
- 标签、proxy 或可用时点不明确；
- 缺失、零值或结构性空白复杂；
- 问题间共享数据接口；
- 聚合方式可能改变排名、策略或答卷对象。

只有在单表、字段含义明确、连接和时间风险都很低时，才可采用精简模式：一个数据管道实现者、一个独立验证者、Leader 综合。即使精简，也不能取消原始材料只读、处理留档和独立复核。

## 10. 变更与局部回滚

- 字段语义错误：重开数据契约及受影响处理；
- 读取或清洗代码错误：修订管道并重新生成下游数据；
- 聚合或筛选改变题目总体：回到数据方案，必要时重开题意；
- 模型提出合理新需求：新增分析视图或数据版本，不直接改共享数据；
- 目标量无法由附件构造：重开路线或题意，不制造标签；
- 题间接口不兼容：回到最早产生该接口的上游问题；
- 仅工程文稿错误：修正文稿，但不能反向改数据迎合叙述。

所有旧报告、失败处理和被替换版本都保留。Leader 说明当前采用哪一版、为什么以及哪些下游产物需要重跑。

## 11. 数据交接后的停止边界

`data/data-handoff.md` 完成后，数据模块停止主动扩张。后续模型若提出数据变更，只通过明确的数据变更请求重新进入本模块。

本模块不负责：模型训练、超参数选择、优化求解、正式模型验证、论文级绘图、答卷生成或正式论文写作。
