# C 题深读协议

## 0A. 来源封箱

Leader 记录题面、附件、数据说明、答卷模板、赛事规则和用户补充的版本、哈希与定位方式。原件只读；OCR 或转写另存，并保留映射。

封箱只说明材料在哪里，不解释其含义。收到新版材料时生成新 snapshot，并只让受影响角色重读。

## 0B. 原子化阅读

字面契约官逐句保留动作、对象、范围、量词、单位、时间、限定语、例外、显式约束和交付格式。不要把“合理、最优、综合、预测、判定”等词直接翻译成某个模型。

原子化是为了能回到原文，不要求把所有发现拆成固定 ID 对象。角色可以使用页码、表名、字段名或自定义短标签引用。

## 0C. 两轮隔离盲读

W1 和 W2 只看原始材料、来源清单和自己的 task brief。每个角色回答本职最低问题，同时自由报告：

- 当前最危险的误读；
- 当前无法由材料决定的地方；
- 任务单未预见但可能更重要的新发现。

盲读的目标是扩大解释空间，不是尽快一致。

## 0D. 每问做到多少

答卷范围官对每问讨论四层：

1. 题面回答下限；
2. 让结论可辩护、后续必须准备的证据；
3. 只为真实风险、歧义或下游需要服务的增强；
4. 继续增加复杂度已不改变答案时的停止线。

这些是审议问题，不是已知评分门禁。若不同解释改变回答下限，应保留多套版本。

## 0E. 竞争解释

对动作词、对象、总体、时间窗、粒度、单位、proxy 或模板有歧义时，形成至少两种认真可辩护的读法。不要制造明显稻草人。

每种读法要说明来源、会改变的答案、变量、约束和题间关系，以及什么观察可能区分。若还有第三种或完全不同的结构，不受两分法限制。

## 0F. 正反题链

正向问每问产生什么、谁消费；反向从最后一问问完成交付需要什么。重点检查：

- 删除前问后，后问是否仍能原样完成；
- 上游输出能否按主键、粒度、单位和时间被下游使用；
- 前问是否只是叙事背景，或实际在生成候选集、参数、约束、场景、评价依据；
- 是否存在非线性、反馈、并行或共享隐变量等新结构。

最后一项必须开放报告，不能因为既有依赖分类没有位置而省略。

## 0G. 开放挖坑

先问“框架之外还可能错在哪里”，再看已知坑点。重点搜索但不限于：文字量词、粒度、时间、proxy、泄漏、因果、约束、可行域、模板、未使用字段、结构性零值和重复观测。

一个有效攻击至少说明具体目标、题内线索或反例、失败机制、影响和区分方式。没有发现时写检查过什么，不写“已通过”。

## 0H. 定向质询

推荐配对：字面契约 ↔ 答卷范围、题链 ↔ 数据法证、数学结构 ↔ 字面契约、红队 ↔ 任何高影响判断。

Reviewer 先钢人化，再攻击。提出原判断的角色复核一次，可以承认、修订、用新证据辩护或建议探针；原始攻击不得删除。质询过程中出现的新问题另列，不强迫它回到原争议。

## 0I. 最小消歧

只执行能改变理解的低成本检查：表头、主键、重复次数、时间范围、单位、模板尺寸、连接覆盖、玩具例子或边界反例。

执行前先写：不同结果分别怎样改变理解；什么结果仍然无法区分。禁止训练、优化、全量特征工程、正式结果和论文图表。

## 0J. 暂定题意基线

Leader 使用开放式 Markdown 基线，逐问说明：

- 真正要回答什么；
- 做到什么程度；
- 怎样与其他问题交换信息；
- 数据支持和不支持什么；
- 当前采用、保留和禁止偷偷默认的解释；
- 已发现的陷阱与仍开放的搜索方向；
- 什么新证据会重开。

最后必须有“任务框架之外的新发现”章节，链接对应原始 memo。基线是当前执行版本，不是题意正确证明。
