# 宽候选路线与人工模型决策协议

## 1. 入口与边界

只有暂定题意基线已经说明每问要什么、做到多少、怎样串联和保留哪些分支后，才开始候选路线设计。

本阶段负责打开模型思路、用文献和真实人的意见校准候选，并把选择权交给用户；不训练、求解、调参、正式验证或写作。所有报告是开放 Markdown，不是固定候选卡或语义 JSON。

## 2. 三段形成候选，不先收敛

### 第一段：结构方向

Route A/B 先不用模型名说明全题对象—关系—决策链、每问目标/状态/决策/约束、题间接口和关键结构风险。随后各自展开多个结构方向，不得先选熟悉或容易实现的模型再倒推题意。

### 第二段：具体候选

每条路线按问题把方向细化为多个真正不同的候选模型族。宽度来自非线性、层级/重复测量、时空依赖、删失/截断、测量误差、优化/决策、不确定性和题间耦合等结构差异，不用岭回归、Lasso、不同超参数制造伪多样性。

每个候选至少讲清：回答对象、结构适配、数据与识别要求、相比 baseline 新增的信息、优势、风险、题间作用、实现/验证代价、拒绝或降级条件。数量不是硬配额；候选过窄时必须说明哪些结构方向被题面或数据排除。

### 第三段：文献对齐后重构

REF0–REF3 不只为已有路线找支持，还必须搜索替代方法、失败证据和 Agent 未想到的模型。W5C 原提案者据此增加、合并、缩小或撤回候选，保留文献无法判定的分歧。任何进入人工汇报的正式候选都必须说明文献状态；找不到直接证据时如实标记，不得补造引用。

## 3. A/B 隔离和结构审查

A 给出最低完整、可贯通全题的宽候选组合。B 独立挑战至少一个高影响结构假设，并给出另一组候选；B 不能只把 A 的算法换成更复杂版本。

Critic 在不读取文献结果的情况下，先钢人化两案，再审：题意是否被暗改、候选是否结构同质、数据/时点/粒度能否支撑、题间接口是否可消费、哪些候选只是工程便利、哪些关键方向被遗漏。发现 A/B 之外的候选时完整报告，不自行选择胜者。

## 4. 文献与真实人的意见

W5A 后同时启动 `Workflow/literature-research.md` 的 REF0–REF3。检索问题同时按路线结构和候选模型族组织，覆盖原始方法、领域应用、官方依据、负面证据、适用前提和替代方法。

REF2 的领域咨询可以缺失并记录缺口；它不等于后面的强制模型决策。Agent 永远不得模拟老师、专家、队友或用户意见。

独立 Literature Evidence Auditor 检查来源真实性、访问状态、可比性、选择性搜证和过度推断。文献数量、引用量、期刊名气、专家身份和获奖论文惯例都不构成投票。

## 5. L2C：Leader 候选模型汇报

W5C 完成后，Leader 使用 `templates/model-candidate-briefing.md` 写 `routes/model-candidate-briefing.md`。它必须保留各路线原文和少数意见，并逐问说明：

- 值得交给人选择的候选模型及其结构；
- 与题意、数据和题间接口的适配理由；
- 文献支持、削弱、替代和仍不可判的范围；
- 优势、劣势、假设、失败风险、实现与验证成本；
- 竞赛价值来自什么题目结构，而不是复杂度或模型名；
- Leader 推荐的主选、备选/敏感性选项及理由；
- 被暂不推荐但仍值得人知道的候选，以及不推荐理由。

Leader 不能只展示自己的首选，也不能因为依赖尚未安装、代码较难或 baseline 没报错而隐藏更适配的候选。

### 5.1 完整材料与聊天展示是两项交付

`routes/model-candidate-briefing.md` 是完整依据；另用 `templates/model-selection-presentation.md` 写 `routes/model-selection-presentation.md`，作为将原样发到用户聊天中的决策正文。文件存在不等于已经展示，不能用“推荐组合＋详情见文件”替代下列内容：

- **全部候选去向。** 逐问核对 A/B、Critic、文献新增和 W5C 中实际考虑过的候选，列出名称及主选、挑战、baseline、敏感性、暂缓或撤回去向。合并时保留原名称、映射和理由，不能用一个笼统标签吞掉结构不同的选项。“全部”是本次实际候选，不是枚举所有算法；不设候选数量配额。
- **重点比较。** 每问挑出能改变选择的几个结构不同候选（包含最强竞品）直接比较：解决什么、比其他方案多解决什么、优势、主要假设/劣势、数据限制、实现与验证成本、失败或切换条件。只有一个可行候选时解释其他候选为何排除；不为凑表虚构选项。暂缓项可一句话，主选不能占满汇报而竞品只剩名字。
- **论文与判断相连。** 重点比较实际依赖的每篇论文，在对应候选附近展示标题、作者/年份、可点击 DOI/URL、实际核验层级（元数据/摘要/全文），以及支持、削弱或不能推出的具体部分。直接来源链接和 source-note 定位同时保留；只有作者名、REF-ID、文献数量或目录链接不算展示依据。无已核验来源时明确“待补”，不编造引用；全文可访问不等于本轮已读全文。完整报告另保留全部检索来源的去重索引及未采用原因。
- **可核验的取舍变化。** 用简短的“原候选/预期 → 文献或审查带来的变化 → 当前推荐及未决条件”说明当时的考量，并链接已落盘记录；这是决策依据摘要，不是隐藏思维链或原始聊天转储。说明哪些判断未改变及为什么，不能事后编造转折，也不能把建模前预期写成已经实测胜出。
- **推荐与选择权。** 比较之后给出逐问建议、保留的分歧、最值得先验证的区分问题和请用户决定的范围；完整报告链接只承载扩展细节，不能承载上述必需内容。

篇幅优先压缩背景、套话和重复说明，不删候选、关键反证或文献影响。可以用紧凑表格和短段落，不强制固定字段、评分或篇数。内容较长时按问题连续展示，全部展示后再请求 H1；“精简”不等于允许把重点比较和论文考量全部移到链接中。使用用户当前界面可访问的文件链接；本地聊天用实际产物绝对路径，不能直接粘贴脱离文档后失效的相对链接。

### 5.2 发送前核对与版本

Leader 对照原始路线、W5C 和已审 source notes，自查用户仅看聊天能否知道：实际考虑了哪些方案、关键优劣、查了哪些论文、论文怎样影响取舍、还缺什么证据。若不能，先补展示正文，不以机械检查通过替代此审查，也不新建“人工决策 Agent”。回归审读示例见 `tests/fixtures/model-selection-presentation-review.md`。

发送前运行 `python3 scripts/check_workspace.py <run_dir> --stage model-briefing --json`，只检查上游报告、完整 briefing、展示正文和来源说明非空；此时不要求、更不能提前伪造 human decision 或 route handoff。检查成功不是已发送、已阅读或语义充分的证明。

展示正文注明本轮 H1 与完整 briefing 版本，按该正文实际发送后停止；尚未发送的文件只能称待发送稿。收到真实回复后，在 `routes/presentations/<H1版本>-presentation.md` 与 `<H1版本>-briefing.md` 保存对应两份不可覆盖快照，H1 决策记录链接这些版本与实际消息定位。先保留用户所回应的版本，再做补充或升版，不能从已改过的工作稿倒推原展示；无法还原时如实记缺口。平台不提供消息 ID/精确时间时写明限制，不伪造，也不因缺 ID 阻塞已收到的真实回复。重开 H1 或重发实质修订必须升版；若展示遗漏影响授权范围，补充展示并请用户确认受影响部分，不能把旧批准自动扩成新授权。

历史 run 没有展示记录时只记录证据缺口，不回填虚构的“当时已展示”。旧 `route`/`data` 机械检查对缺失展示正文仅提示，不核验快照与真实消息的对应；本规则生效后的新 L2C 或重新 H1 必须走上述发送前检查，不因兼容提示跳过展示责任。

## 6. H1：真实人工强制决策

候选汇报完成后，Leader 将 run 状态置为 `AWAITING_HUMAN_MODEL_DECISION`，按第 5 节把决策正文直接展示在聊天中并附完整汇报链接，然后停止。没有真实回复时，不得写 `routes/human-model-decision.md`，不得进入 L2、D0 或 M0。

用户可以：选择一个主模型；选择主模型加备选/敏感性模型；要求补文献或扩展某类候选；全部否决并退回 W5A/REF；或给出时间、依赖和实现约束。Leader 只能根据真实回复使用 `templates/human-model-decision.md` 忠实记录，不得代签、猜测或把沉默当批准。

机械 checker 只能检查文件存在且非空，不能证明展示实际送达、用户已阅读或决定来自真人。Leader 保留实际展示版本、原始用户消息和来源说明；不得将磁盘上较完整或事后修订的报告冒充用户当时看到的内容。

## 7. L2：按人工决定冻结路线

取得真实人工决定后，Leader 才能使用 `templates/route-handoff.md` 写 `routes/route-handoff.md`。交接必须区分：

- 人工选择的主模型；
- 人工保留的备选、挑战或敏感性模型；
- 只作 baseline 的简单模型；
- 明确放弃和暂缓的候选；
- 数据工程必须保留的字段、粒度和接口；
- 需要重新请求人工决策的触发器。

后续发现数据无法支持、核心模型不收敛或必须改变模型家族时，使用 `templates/model-selection-change-request.md` 写 `routes/change-requests/REQUEST-ID.md`，重新进入 H1。Agent 可以在同一人工授权模型内部做合同允许的实现与参数调整，但不能静默换成更容易的模型。

重新 H1 同样遵守第 5 节；重点展示受影响问题的旧选项、新候选、对应论文和新证据如何改变取舍，未受影响问题说明沿用的已授权版本，不能只报一个替代模型名。

L2 完成后前半程停止。
