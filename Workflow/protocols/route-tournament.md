# 路线竞标协议

## 1. 入口与边界

只有暂定题意基线已经说明每问要什么、做到多少、怎样串联和保留哪些分支后，才开始路线竞标。

竞标选择结构路线和模型族，但不训练、求解、调参、正式验证或写作。路线报告是开放 memo，不是固定路线卡。

## 2. 先结构，后模型

Route A/B 第一部分先不用模型名回答：

- 全题的对象—关系—决策链是什么；
- 各问目标量、状态量、决策量、约束和输出是什么；
- 题间怎样交换对象、粒度、单位和不确定性；
- 核心结构假设与最弱环节是什么。

结构写清后，再为每个模块选择可解释 baseline、暂定主模型族和备选，并说明为什么匹配、什么情况会拒绝。不能先想到熟悉模型，再倒推题意。

## 3. A/B 隔离

A 提出最小完整、可贯通全题的路线。B 独立挑战至少一个高影响结构假设，例如目标定义、分析单位、时空粒度、层级、依赖、风险表达、决策耦合、可行域或 proxy 边界。

B 不能只换更复杂算法。如果确实找不到可辩护的结构挑战，应报告尝试过什么、为何被题面或数据排除；Leader 更换挑战者或重开基线，而不是伪造备选。

两者除最低必答问题外，可以自由提出第三路线、共享模块、新约束、意外数据要求和其他未预见发现。

## 4. 路线审查

Critic 先分别写两案最强版本，再检查：

- 是否暗中改写题意基线；
- 数据能否在正确时点、粒度和单位构造所需量；
- 上下游接口是否真实可消费；
- 模型族是否服务结构，还是用算法名掩盖假设；
- 假设、proxy、泄漏、可证伪性和最弱环节；
- 是否能落到每问 answer object；
- 切换和局部回退成本。

审查中发现 A/B 之外的新结构时，完整报告，不能因“本轮只比较两案”而删除。

## 5. 最小判别计划

为真正会改变路线的分歧设计最小观察：两案分别预期什么、最少需要什么数据、什么结果切换、什么结果让两案同时失效、成本和停止点是什么。

本阶段只设计路线 pilot，不执行正式模型。若判别量不可观测，保留兼容两案的共同安全核心或重开题意。

## 6. Leader 路线交接

使用 `templates/route-handoff.md`，至少说明：

- 当前暂定主路线和仍存活的挑战路线；
- 两案真正的结构差异；
- 各模块 baseline、主模型族、备选和拒绝条件；
- 共同安全核心；
- 关键假设、少数意见和未分类的新发现；
- 切换、重开和局部回滚条件；
- 下一阶段第一个需要验证的问题；
- 尚未执行的工作。

这些是最低交接责任，不限制报告增加第三路线、其他风险或新的模型结构。

路线交接完成后立即停止。
