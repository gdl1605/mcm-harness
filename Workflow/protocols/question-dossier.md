# 逐问题意档案

## 1. 定位

逐问题意档案是一份持续更新的 Markdown 研究 memo，不是 schema。它帮助 Leader 和后续路线团队理解每问，但不能限制角色只能讨论预设字段。

可以使用 `templates/question-dossier.md` 起步，也可以改变结构。唯一要求是最低问题可被找到，且新增发现不会因为没有栏目被丢弃。

## 2. 每问最低问题

### A. 字面契约

- 原文动作、对象、范围、量词、时间、单位、限定语和交付是什么？
- 哪些是显式约束，哪些只是推断？
- 题面没有要求或当前不能宣称什么？

### B. 真正目的与作答深度

- 这一问最终要支持什么判断、决策或知识主张？
- 评阅者最终能定位的 answer object 是什么？
- 回答下限、可辩护证据、竞争性增强和停止线分别是什么？

### C. 题间串联

- 上游提供什么，下游消费什么？
- 接口的对象、主键、粒度、单位和时间是否兼容？
- 删除本问后，其他问题会怎样变化？

### D. 数据、变量与约束

- 哪些量可观测、派生、潜在、代理、状态或决策量？
- 它们在决策时点是否可得？
- 哪些约束来自题面，哪些依赖某种解释或领域常识？

### E. 竞争解释与陷阱

- 有哪些认真可辩护的替代读法？
- 各自会怎样改变答案、粒度、约束或路线？
- 当前最危险的错误路径、反例和最低成本消歧是什么？

### F. 当前工作版本

- 当前暂用什么，为什么？
- 哪些分支仍存活？
- 什么不能偷偷默认？
- 什么新证据会重开？

## 3. 开放扩展区

每份 dossier 必须保留一个不限定类型的扩展区，用于记录：

- 现有问题分类没有覆盖的发现；
- 反常细节和无法解释的附件；
- 新的题间结构或第三种解释；
- 角色认为 Leader 还没有问对的问题；
- 后续模型路线必须知道、但当前无法归类的事项。

扩展区不是附录垃圾桶。若内容影响大，应提升到报告主体，同时保留原始 memo 链接。

## 4. 建议骨架

```markdown
# Q? 题意档案

## 一句话工作理解
...

## 最低问题 A–F
...

## 实质分歧与少数意见
...

## 已做或建议的消歧
...

## 当前工作版本与重开条件
...

## 任务框架之外的新发现
...

## 原始报告与来源定位
...
```

这只是起始骨架，不是输出边界。
